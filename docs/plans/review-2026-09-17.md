# Code and conversation review — 2026-09-17

Written after the tier ladder completed (tiers 1-3, 5-7; tier 4 skipped as a
measured no-op). Every item below was found by probing shapes the corpus does
not contain, not by re-reading notes.

Method that found things: take a C idiom the fixtures happen to omit, run it
through the tracer, and check the output against what the source says must be
true. Three of the four bugs surfaced within minutes that way. Reading the code
alone would not have found them.

---

## Bugs

### B1 — A null pointer destroys pointee recovery for every call  — FIXED

```c
int maybe(pair_t *p) { return p ? p->a : -1; }
maybe(&q);   /* valid   */
maybe(0);    /* NULL    */
```

The tracer emitted `arg0` and **nothing else** - no `arg0[..]`, no fields - even
for the call with a valid pointer.

Cause: `MemoryMap.classify(0)` returns SCALAR, and `classify_slot` demotes a
slot to SCALAR if *any* observation was not POINTER. One NULL therefore poisons
the whole slot.

The comment justifying it said null must be scalar "while the malloc stub still
returns 0". **That rationale expired when tier 5 landed** - the allocator now
returns real addresses, so a null argument means the program genuinely passed
NULL. The code outlived its reason by two tiers.

Fix: null is neutral in aggregation - it neither promotes nor demotes. A slot is
a pointer if at least one observation was pointer-shaped and none was a
non-null scalar. The null sample still emits `nonsensical`, which is correct and
is what Kvasir does.

### B2 — Out-parameters are invisible  — FIXED

```c
void fill(pair_t *p, int v) { p->a = v; p->b = v * 2; }   /* writes only */
```

Recovered no pointee at all. Only `UC_HOOK_MEM_READ` was hooked, so a field
that is written but never read leaves no footprint.

Out-parameters are a common C idiom and Kvasir reports their fields, so this was
a straight recall loss on a whole category of function.

Fix: hook `UC_HOOK_MEM_WRITE` as well. A written offset is evidence of a field
exactly as a read one is.

### B3 — Pointee capture depended on arity  — FIXED during phase 7

Capture consulted `arity()`, which is learned from executed instructions and is
`(0, 0)` when a function is entered. Every function lost its **first** call's
pointee; a function called **once** lost everything to `nonsensical`. Recorded
here because it is the same class as B1 and B2 - a dependency on information
that does not exist yet at the moment it is consulted.

Fix: capture keyed by raw slot index, classified against the live memory map.
**Capture broadly, emit narrowly.**

### B4 — Allocation size used last-write-wins  — FIXED during phase 7

`pointee_size` was stored per (function, argument) and overwritten per call, so
a parameter pointed at a 20-byte object and later a 12-byte one could be
credited with fields existing in only one. Now keeps the minimum seen.

## Verification after the fixes

- 333 tests pass (up from 327: four unit tests for null aggregation, two e2e
  regressions on a new `tests/test14.c`).
- `./test.sh --tier 7` at 0 failures across 18 binaries.
- All seven lower-tier goldens byte-identical, so neither fix perturbed a tier
  below the one it belongs to.
- Two pre-existing tests asserted the old null-is-scalar contract and were
  rewritten rather than deleted; they now pin the new distinction.

`tests/test14.c` carries both shapes with the reasoning in its header comment,
so the next person to touch pointee classification sees why null is neutral and
why writes count.

## Untested paths

- **32-bit.** Every tier above 1 is gated on `is_64bit`, and no 32-bit
  toolchain is installed, so the guards have never been executed. They are
  believed correct by inspection only.
- **Two pointer arguments into the same object.** `_hook_mem_deref` returns
  after the first match, so a `memcpy(dst, src, n)` shape would attribute every
  access to whichever argument is checked first.
- **Pointer-to-pointer.** Only one level of dereference is modelled; `char **`
  would recover the pointer values, not what they point at.
- **Float and SSE.** Never captured at any tier. A function doing FP arithmetic
  is invisible, and no fixture contains one.
- **Recursion combined with pointees.** `test11` is recursive but scalar;
  nothing exercises both at once.

## Deliberate limits, stated rather than hidden

- **Signedness is not observable from the VALUE** - the bits are identical.
  It IS observable from the operations applied to the value (`shr` vs `sar`,
  `seta` vs `setg`, `movzx` vs `movsx`), which the tracer does not yet watch;
  see docs/EVALUATION.md section A. Currently a high-bit `unsigned` reads back
  negative, pinned by `test_unsigned_is_knowingly_wrong`.
- **A fixed-size array with no length parameter stays struct-modelled.** The
  discriminator needs a correlated length argument, and no evidence separates
  `int p[2]` from `struct {int a, b;}`.
- **Non-contiguous footprints stay struct-modelled.** `varying_len` reads only
  `arr[n-1]`, so its offsets do not tile from zero.
- **Trailing dead arguments are invisible at -O1+.** At -O0 the prologue spill
  saves them; the corpus is entirely -O0, which flatters the heuristic.

## Divergence from the oracle, on purpose

`flags is_param` makes Daikon drop non-unit coefficients and suppress correct
invariants. Kvasir sets it and is wrong; we do not set it and are right. Any
scoring must account for the divergence rather than treating Kvasir as ground
truth. See the entry in `README.md`.
